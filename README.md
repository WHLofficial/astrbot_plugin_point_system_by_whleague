# 积分系统插件 by WHLeague

> 一个功能完整的群聊积分系统，支持签到、抽奖、兑换、排行、生日、口令、打劫等多项功能。当前版本 **v0.5.8**。

## 功能列表

**积分获取**

- 每日签到：固定/随机积分，首签、每日首签、连签（有上限）、每 7 天奖励，附每日运势；**全局限签**（同用户跨群同日仅 1 次，连签跨群延续）；每日刷新时刻可配置（默认 04:00）；反馈含**当日签到排名 / 连签天数 / 当前积分**
- 彩蛋事件：签到概率触发欧皇/非酋事件，±大量积分；触发概率与保底次数为配置项（欧皇/非酋各自独立，默认 0.005 / 200，0=关闭保底；`/设置` 可调）
- 活跃奖励：合规群消息概率获得随机积分（默认 1~5），用户冷却 + 全局冷却
- 每日口令：当日动态关键词，消息命中即得，**全局限领**（同用户当天任意群仅 1 次）
- 日期口令：日期范围 + 关键词 + 概率，签到联动触发，支持跨年
- 生日奖励：生日当天签到额外积分，定时播报寿星
- 打劫：无前缀「打劫 @目标」抢群友积分（成功抢得部分积分、失败扣成本；成功率/收益曲线/门槛/冷却/每日上限均可配置；目标可被抢成负分并联动负分头衔）；**防集火**：目标每日被劫上限（默认 6 次）+ 收益递减（每被成功打劫一次后续收益衰减 25%）

**积分消费**

- 个人抽奖：口令验证，五档权重概率（特等奖/一等奖/二等奖/三等奖/参与奖），每日限次按 QQ 全局统计（跨群共享）；反馈含**消耗 / 积分变化 / 当前积分**
- 兑换玩法：库存原子扣减，兑换记录核销/驳回三态（通过/驳回可互切，**驳回退回积分并恢复库存**），**核销/驳回后通知兑换者**（默认原兑换群 @通知，可配置为私信；全局管理员可跨群核销；发送失败发警告）；成功反馈含**订单号 / 剩余库存 / 积分余额**与"联系管理员核销"提示；**管理员查看兑换记录时展示兑换者**（列表行尾与详情均显示昵称+QQ，昵称实时解析：记录所在群 → 管理员当前群 → 回退 QQ）

**排行与统计**

- 群内排行：Top 10，注册用户不足 3 人自动回退全局排行；展示群昵称（card → 昵称 → QQ 号回退）；**查看排行时最后一行显示触发者自己的排名**（未上榜引导签到）
- 我的积分：无前缀发送「我的积分 / 积分查询」，展示群昵称+QQ / 当前积分 / 累计签到 / 连签 / 今日签到 / 本群排名 / 最近 5 条本群流水
- 发言统计：静默统计群内发言（普通聊天/指令/@机器人/图片表情均计入，机器人自身与空消息不计；计数由独立的高优先级 handler 执行，因此「签到」这类命中后会中断派发链的触发指令也照样计数），无前缀发送「我的发言 / 发言统计」查看今日 / 本周 / 本月 / 上月 / 累计发言数、本群排名、发言称号、活跃画像（占本群比例与百分位）与活跃轨迹（最近发言 / 活跃天数 / 连续天数 / 最高单日）；周期口径统一按业务日（同签到的刷新时刻，默认 04:00）切分，统计按 QQ + 群隔离，数据从本功能上线后开始累计
- 发言里程碑播报：本群累计发言跨过称号档位时主动 @ 本人播报（档位与发言称号同源，最低那一档不播报，一次只报最高档）；逐档幂等、先登记后发送故发送失败不补发（至多一次，宁可漏一条也不重复 @ 全体）；文案由 `speak_milestone_template` 配置，支持 `{total}` / `{title}` / `{rank}` 三个占位符（未知占位符原样保留）；**默认关闭**，开启后对老成员做惰性静默基线——已在档位之上的成员不会被回溯补发，只有真正跨过的那一刻才播报
- 积分流水、签到统计（人数/签到率/首签/连签王，昵称展示）

**管理**

- 管理员指令：独立管理员名单，增减积分，兑换/口令/配置/日期奖励管理
- 数据清空：`/清空数据`（本群，清零本群成员共享积分与群级记录，积分全局共享故其他群同步归零；发言统计与里程碑登记一并清除）与 `/清空全部数据`（全局），验证码二次确认，清空前自动备份并恢复负分头衔名片

**系统机制**

- 无前缀触发：**严格匹配**——消息必须完全等于触发词（或「口令±关键词」形态）才触发，打劫为「关键词 + @目标」形态（@ 段不计入文本匹配），普通聊天含关键词字样不再被拦截
- 口令保留字校验：口令不能与签到/抽奖/排行/打劫触发词相同或构成组合形态，杜绝口令死锁
- 积分一号跨群共享：按 QQ 全局唯一账户，余额/累计获得/签到状态跨群一致，负分头衔跨群联动（回正后清除所有群头衔并恢复原名片）
- 负分联动：负分禁止抽奖/兑换/活跃奖励/口令（管理员扣分亦可扣成负数），自动设置"群女仆X号"名片，回正后恢复
- 自动备份：多目标目录，`VACUUM INTO` 一致性快照（默认每天 04:00，可配置），每目录仅保留最近 N 份（`backup_keep_count`，默认 30）
- 配置可视化：AstrBot WebUI 与 `/设置` 指令双向同步，热生效
- 昵称防注入：所有群昵称/发送者昵称拼装点（运势/排行/查生日/活跃奖励/打劫）统一剥离控制字符，昵称无法构造多行伪造消息

## 快速开始

### 安装

将本插件目录放入 `AstrBot/data/plugins/` 下，重启 AstrBot 或热重载插件即可。

依赖会自动通过 `requirements.txt` 安装（仅 `aiosqlite`）。

### 基本用法

```
# 签到（无前缀触发）
签到

# 抽奖（需要口令，默认 whl）
whl抽奖

# 查看排行
排行

# 查看我的积分
我的积分

# 打劫群友（@ 目标）
打劫 @目标

# 查看可兑换物品
/商品兑换

# 兑换物品
/商品兑换 1

# 查看积分流水
/流水

# 查看签到统计
/签到统计

# 设置生日
/设置生日 08-15

# 管理员：加分
/加分 @用户 50

# 管理员：设置每日口令
/设置今日口令 红包 10
```

## 配置项

所有配置均可通过以下两种方式修改，双向同步、热生效：

1. **AstrBot WebUI**：插件设置页（`插件 → 积分系统 for WHL`）可视化查看与编辑
2. **指令**：`/设置 <键> <值>`、`/查看配置`

> 每日刷新时刻（`signin_refresh_time`）统一作用于签到、连签、每日首签、每日口令、抽奖次数等全部每日逻辑；一天区间为该时刻至次日同一时刻。刷新时刻、备份时间、生日播报时间均**按宿主机本地时区**计算。

## 竞猜系统同步

与 WHL 竞猜系统（[WHL-Daily-Activities-System](https://github.com/WHLofficial/WHL-Daily-Activities-System)）对接，插件作为**积分真源**：

- **入账**：竞猜系统发放奖励/冲正时 POST `/sync/credit` 到本插件（HMAC-SHA256 验签，±300 秒时间窗），按 `payout_id` 幂等入账；与 `sync_ledger` 流水同事务写入，冲正余额不足时回滚返回 409
- **对账**：竞猜系统每日定时 GET `/sync/summary?date=YYYY-MM-DD`，按东八区日期返回各 QQ 净额（含冲正负数）。响应形如 `{"date":"YYYY-MM-DD","items":[{"qq_id":"<QQ>","total":<净额>}]}`；`total` 为当日净额，含冲正负数、可为负，**无 `count` 字段**。该字段名是对账接口的既定形状，**不要改名**（改名会导致竞猜系统每日对账取不到实发数据）
- **绑定**：一次性码（10 分钟、一码一次）+ 群内「**绑定 <码>**」完成 QQ ↔ 账号绑定（群聊裸发或带 `/` 前缀均可触发）。目标随 `bind_claim_url` 切换：**已配置** → 绑定码在统一认证中心网页生成，核销走认证中心 `POST /api/bind/claim`（`bind_secret` 独立验签）；**留空** → 沿用竞猜网页老路
- **解绑**：群内发送「**解绑**」直接解除本 QQ 的绑定；或在认证中心网页点「解绑此 QQ」后，群内发送「**解绑 <6 位码>**」完成确认（增量 11，走认证中心 `POST /api/identity/unbind/confirm`）。两种方式均仅认证中心绑定模式下可用，积分余额不受影响；换绑 = 先解绑，再到认证中心生成新码重新绑定
- **战报**：插件每分钟轮询竞猜系统待发战报，原样转发到 `sync_report_groups` 配置的群，**全部群发送成功才**确认（ack）；失败下轮重拉

### 配置与部署

1. WebUI 插件配置中开启 `sync_enabled`，填入与竞猜系统一致的 `sync_secret`
2. `sync_report_groups` 填战报目标群号；`sync_platform_id` 填消息平台实例 id（WebUI 消息平台页可查）
3. 服务器上用 cloudflared 把公网域名指到本机端口：`cloudflared tunnel` 规则 `astrbot.whleague.win → http://127.0.0.1:9991`，竞猜系统 `SYNC_BASE_URL` 配 `https://astrbot.whleague.win`
4. 验证：`curl https://astrbot.whleague.win/sync/summary` 应返回 `401 {"error":"bad sign"}`（说明服务可达且验签生效）
5. 排查「127.0.0.1:9991 连不上」：先确认 WebUI 里 `sync_enabled` 已开且 `sync_secret` 非空——只开开关不填密钥时插件会打 `[sync] sync_enabled 已开启但 sync_secret 为空，同步不生效` 并跳过启动，此端口不存在，Tunnel 无端口可转发，竞猜系统对账页会显示「插件不可达」。日志检索用 `[sync]` 前缀，启动成功行是 `[sync] http server listening on 127.0.0.1:9991`。若公网地址返回 `530` 且正文为 `error code: 1033`，是 Cloudflare 边缘找不到已连接的隧道（cloudflared 未运行），与插件无关，需先拉起隧道再验证
6. Docker 部署注意：若 AstrBot 跑在容器中且未用 `network_mode: host`（即独立网络栈），容器的 `127.0.0.1` 与宿主机的 `127.0.0.1` 是两套独立网络栈。插件绑在容器 loopback 上时会正常打印 `[sync] http server listening on 127.0.0.1:9991`（该行在 `site.start()` 成功后才打印，绑失败会打 `failed to listen`），但宿主机上 `curl 127.0.0.1:9991` 会被**立即拒绝**（0 ms，不是超时），cloudflared 也转发不到。此时须把 `sync_listen_host` 改为 `0.0.0.0`（在容器内绑定），并在宿主机侧只发布到回环：`ports: ["127.0.0.1:9991:9991"]`。注意仅靠 `-p` 不改监听地址是无效的——Docker 端口发布的目标是容器的 eth0 地址而非其 loopback，绑在容器 loopback 上的服务发布出去仍然够不到。若 cloudflared 与该容器在同一 compose 网络，也可不发布端口，直接让 Tunnel 指向 `http://<容器名>:9991`

> 安全：`sync_secret` 只存 AstrBot 托管配置，不进任何 git 仓库、不打日志；HTTP 默认仅监听 `127.0.0.1`，由 Tunnel 对外暴露；所有端点先验签。容器部署按第 6 条监听 `0.0.0.0` 时，须由宿主机侧的端口发布把可达范围限制在回环，不得暴露到公网。

## 数据存储

- **数据库文件**: `<AstrBot数据目录>/plugin_data/astrbot_plugin_point_system_by_whleague/points_system.db`（SQLite，WAL 模式），自动创建
- **路径定位**: 优先使用 AstrBot 官方路径 API 定位数据目录，不依赖进程工作目录，云服务器部署无需额外配置
- **自动备份**: 默认每天 04:00（配置项 `backup_time`）备份到配置项 `backup_dirs` 指定的目录，文件名含时间戳
- **备份路径**: 绝对路径直接使用；相对路径基于插件数据目录解析，支持 `~` 展开
- **备份方式**: `VACUUM INTO` 生成一致快照（含 WAL 数据）
- **备份保留**: 每个备份目录仅保留最近 `backup_keep_count` 份（默认 30，0=不清理），超出自动删除最旧备份（仅清理本插件 `points_system_*.db` 命名文件）
- **数据库版本**: 当前 schema v5（积分一号跨群共享：`accounts` 表按 QQ 全局唯一账户，`users` 仅存群级数据；v4 起 `redeem_records` 含驳回审计列；v5 起新增 `rob_records` 打劫记录表；v0.6.0 起 `sync_ledger` 竞猜同步幂等账本随建表脚本自动创建，无需版本迁移），旧库首次加载时自动迁移（v4 → v5 纯新增表；v3 → v4 驳回审计列；v2 → v3 多群余额取 MAX 合并；v1 → v2 负分头衔原名片、流水操作人字段），升级前建议先备份数据库

## 预留设计

以下为已定稿但**尚未实现**的设计，供后续开发直接落地。

### 不活跃每日定时提醒

按业务日每天定时找出「曾经活跃但最近一段时间没说话」的成员并 @ 提醒，数据源复用发言统计的 `speak_daily`。

- **触发**：读 `inactivity_reminder_time`（`HH:MM`，默认 `20:00`，非法回退默认）注册名为 `inactivity_reminder` 的 cron 作业，形态照 `main.py` 里备份与生日播报的 `_start_cron_jobs`；`_remove_cron_jobs` 的属性元组与 `_cleanup_stale_cron_jobs` 的名字过滤都要加上该作业名。
- **判定**：按群取每个成员 `MAX(stat_date)`（`speak_daily` 只有发言日才有行，即最后发言业务日），`julianday(今日业务日) - julianday(MAX(stat_date)) >= 阈值天数`。只对曾经发言过的成员提醒，不 @ 从未发言的人。
- **幂等**：新表 `speak_inactivity_log(group_id, qq, reminded_date, last_active_date, UNIQUE(group_id, qq, reminded_date))`，靠 `INSERT OR IGNORE` + `rowcount` 守卫按业务日去重。
- **降噪**：每群每天最多提醒 `inactivity_reminder_limit` 人（默认 3）；群白名单 `inactivity_reminder_groups`（空 = 全部群，形态照 `sync_report_groups`）；发送时刻按业务日边界（`signin_refresh_time`）之后才生效，避免撞上跨日刷新。
- **文案**：`inactivity_reminder_template`，占位符 `{name}` / `{days}` / `{total}`，@ 本人。
- **失败重试**：发送成功才写标记行，形态照 `_cron_birthday_announce`。
- **待拍板**：阈值天数、每群每日提醒上限、群白名单、是否 @ 本人、具体发送时间。
